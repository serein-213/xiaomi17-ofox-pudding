## 二、三个解密根因

### ① `TW_USE_FSCRYPT_POLICY := 2` 缺失（编译期）
设备目录策略全为 **v2**，缺此开关时 `fscrypt_policy` 编译成 **v1 结构体** ⇒ 永不匹配。
配套：`TW_INCLUDE_CRYPTO_FBE` / `TW_INCLUDE_FBE_METADATA_DECRYPT` / `BUILD_BROKEN_DUP_RULES`
来源：公开参考 `github.com/YuKongA/twrp_device_xiaomi_sm8750_thales`（109★）

### ② 内核 fscrypt 密钥**绑定在挂载实例(superblock)上**
解锁流程: 装密钥 → `Setup_Data_Media()` **卸载+重挂 /data** ⇒ 密钥失效 ⇒ 名字退回密文。
修复：每次重挂后重装 —— `[0121]` DE 密钥、`[0125]` CE 密钥（后者是 `/data/media/0` 的关键）。
> 线索来自用户记忆："有一次正常解密，只是需要手动挂载 storage"

### ③ keystore2 启动竞态
metadata 解密可能早于 keystore2 注册 ⇒ `/data` 挂不上需重启。
`[0126]` 加等待（正确服务名 + 廉价预判 + 墙钟超时）。

## 四、UI 适配 1220x2656（圆角 + 居中挖孔）

| 问题 | 根因 | 修复 |
|---|---|---|
| 卡片/头像变形 | 主题 1080x1920(16:9) 与屏幕 1:2.18 不符；且 `<resolution>` 缺 `resizing` 属性导致 scale_w=1.1296 / scale_h=1.3833 **非等比** | `[0134]` `<resolution width="1080" height="2351" resizing="1"/>` ⇒ 两者 =1.1297 |
| 解密界面导航栏偏上 | `data.cpp:810` 启动时用宏 `OF_SCREEN_H`(默认1920) 覆盖主题 `screen_h` | `OF_SCREEN_H := 2351`（与 ui.xml 一致） |
| 电量/温度被 R 角裁切 | `OF_STATUS_INDENT_*` 默认仅 20px | `:= 64` |
| 居中时钟被挖孔遮挡 | 孔在正中，居中必然被挡 | **[0139] 分列时钟**：新增 `tw_time_hh`/`tw_time_mm` 动态变量，hh 在孔左、mm 在孔右（各偏移 78 设计像素） |
| 封面图底部橙色条 | `original.png` 1080x1920 铺不满屏幕，露出填充色 | 生成 1220x2656 适配版 |
| 启动图定制不生效 | fstab 缺 `/recovery`+`/boot` 条目 ⇒ 解包拿到空 block device；且误加 `AB_OTA_UPDATER` 使分支误判 | 补 fstab 条目 + `OF_AB_DEVICE_WITH_RECOVERY_PARTITION := 1`（实测 magiskboot 成功解出 142MB ramdisk） |

**关键教训**：`placement x=` 属性**不支持算术式** —— `"540-78"` 会被 `atoi` 截断成 `540`，
导致两半叠在正中而"完全消失"。必须用预计算的纯数字变量（`clock_hh_x`/`clock_mm_x` = 462/618）。
